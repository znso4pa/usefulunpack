## 本轮修复

| 问题 | 修复与静态依据 |
|---|---|
| 旧搜索取消后污染新查询 | 新查询分配独立集合；工作线程固定结果集、目录、上限、正则和筛选条件；UI 仍检查当前线程身份 |
| 跨 tab 搜索覆盖归档上下文 | 每个搜索窗口捕获自己的归档、缓存路径、密码和解析映射，点击结果不再读取其他窗口改写的全局上下文 |
| 普通空文件被当成归档占位文件 | 只有缓存目录下的空文件才进入按需解包流程 |
| 更换目录后仍显示旧搜索结果 | 中断旧任务并清理对应结果、续扫状态和进度，目录与结果范围同步更新 |
| 关闭 tab 时异常残留护盾 | finally 释放护盾/遮罩，随后同步其余窗口 |
| 首页长标签挤掉标题 | 限制标签宽度，快捷卡标题单行省略，完整语义仍保留在无障碍描述中 |

## 验收边界

源码调用关系审查不等于编译通过。首页在实际窗口高度和字体倍率下是否刚好一屏、文字是否完整、列表内部滚动、弹窗首帧及跨 tab 触摸行为，仍需后续构建和运行确认。后续运行验收应覆盖快速连续搜索/换目录、两个 tab 同时搜索不同归档、首启未接受提示、关闭有弹窗的 tab、短屏和放大字体。

## 第三轮：取消、晚到回调与完成状态

- 磁盘扫描结果转屏重建：回调执行时检查 Activity、原窗口是否仍显示、所属 tab 是否仍存在；同一旧窗口只排队重建一次，防止关闭后复活或快速转屏打开重复结果框。
- 磁盘扫描取消：区分用户关闭扫描与正常交接结果。扫描步骤明确记录成功、取消或受限目录导致的部分失败；只读结果框不持有已完成任务的运行引用。
- 共享取消回调：结果查看器不再向完成日志追加 CANCELLED；已取消或已结束的意图不重复取消。
- 搜索：无效正则表达式和根目录不可读不会继续显示正常空结果；扫描步骤记录对应失败终态。最后一条排队的进度更新不能覆盖最终结果及不完整提示。

验收范围：组件静态门禁及自测、git diff 空白检查、7 个修改 Kotlin 文件的轻量括号平衡检查（不是 Kotlin 类型检查）、68 份 XML 解析、四语言 735 键一致且无重复、每语言 20 个教程标题/正文分隔。构建 JVM 0；未启动 Gradle、Kotlin 编译或设备复测。当前已安装 APK 不包含本批工作区改动。

## 连续明暗渐变与入场速度

对照 6.0 以前主题：旧实现启用系统背景 dim，由系统处理明暗过渡；tab 隔离后系统 dim 被禁用，自绘遮罩此前只有 VISIBLE/GONE，导致关闭硬切和菜单→设置交接闪亮。新增 DialogScrimMotion 只控制视觉透明度，原窗口、tab、护盾与关闭语义仍由 DialogHost 管理。所有者同帧更新合并、淡出前保留 80ms 交接空档，接管时从当前透明度续接；旧结束回调检查代次，Activity 销毁取消回调。
