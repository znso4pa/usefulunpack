# 文件 Agent 用量验证矩阵

模型代号为 `dsv4.1f`。用量取自模型响应的 `usage`，耗时统计模型请求。缓存命中计入输入，思考计入输出。字段缺失时记为「未知」。矩阵公开合成用例、验收结果和汇总用量，模型身份统一使用代号。原始日志、会话标识、设备信息、端点、密钥和真实路径留在本地。

## 只读基线

单次生成上限为 4,096。测试文件均为合成样例。工作区放入 `tyrano/tyrano.js` 和 `data/scenario/test.ks`，再创建含 `game/dialogue.txt` 和 `assets/image.txt` 的 `sample.zip`。这些文件只需要名称和目录结构，内容可用占位文本。

## 独立上下文验收

每组从空白会话开始，使用独立的合成工作区，保持历史、常驻上下文和手选参考指南为空。第三档验证归档和文件删改，UU/UUT 在单独的第四档用例中验收。所有确认只针对当前合成工作区。能力按可观察的任务拆解、约束遵循、产物验证及失败处理记录。

## 自动回归向量

用本地模拟 Chat Completions 端点检查请求 JSON。真实 token 由模型服务计算，回归使用请求结构和 UTF-8 字节数作指标。

| 变量 | 向量 | 必须满足 |
| --- | --- | --- |
| 历史 × 文档 | 空历史／有新旧历史 × 不选／选一份指南 | 超预算旧历史移除，近期问答保留；选中文档只随首次请求发送；常驻上下文和保留的历史在临时附件之前 |
| 权限和重复读取 | 只读轮次中请求非法工具、正常读工具、重复读 | 非法调用不执行，重复读复用首个结果，工具定义保持在权限内 |
| 纯本地请求 | 四种语言的独立引擎问题、复合任务、指定子目录、常驻上下文、已有历史、附文档 | 只有无额外上下文的新会话里的明确引擎问题可自动走本地 |
| 生成上限 | 默认、覆盖、探针 | 默认 4,096；覆盖值传到同一轮的所有模型请求；连接测试为 256 |
| 活动顺序 | 两次工具调用及三段思考 | 思考和工具事件按回调顺序交错，工具状态更新不改变事件位置 |

```bash
./gradlew :app:testDebugUnitTest --tests com.usefulunpacker.AgentClientTest --tests com.usefulunpacker.AgentSessionStoreTest
```

复测真机时打开消息的「Token 用量」，再到「日志与诊断」核对 `model_usage`。日志同时带每次请求的 JSON 字节数和工具定义数。字节数可定位负担变化，计费分析使用服务提供的 token 数。后续验收在这里追加合成输入、失败与重试、逐请求用量和独立校验结果。

## 单变量成对复验

本轮新增 **36 个真机用例、96 个协议用例、24 个文件与命令用例**。三个数据集各自统计。每种变量都有 A/B 两侧，各做三次独立复验，发送顺序为 A→B、B→A、A→B。真机最多并行三组，每组内按顺序发送。共享缓存与网络时延无法固定，缓存和耗时作为观测值。

## 结论

- E1 发了两次模型请求，输入占总 token 的 95.6%。E2 用现有的引擎探测器直接输出同一证据，省掉 API 往返和全部 token。用户附带指南或需要延续上一轮时，保留模型路径。
- 远程工具流程会重复发送当前权限内的工具、常驻上下文和保留的历史。临时参考文档已放到稳定前缀之后，并在首个回复后移除。A2 两次请求都带 7 个工具定义，加入工具结果后仍从 5,251 字节降到 4,640 字节，模型返回的输入从 1,390 降到 1,144 tokens。缓存是否命中取决于运行环境，单次样本无法估计这一调整的缓存收益。
- 缩小单次生成上限对以输入为主的向量节省有限。后续可用同样的矩阵验证按任务提供最少的工具定义，复杂任务保留扩展工具的能力。工具续轮须保留协议要求的思考字段。
- 在本轮的简单目录读取中，工具定义和续轮的增量都比调低生成上限更明显。优先对照验证按任务缩小模型可见的工具列表，再测结果裁剪和常驻上下文精简。实际授权仍由本地工具检查与确认处理。

## 翻译工作台协议回归（7.1，无实际模型计费）

新工作台只提供读取选中行和提交译文两个草稿工具，第四档权限也不增加文件写入或 UU/UUT schema。本地模拟模型跑通读取 → 提交 → 总结三次请求，断言仅选中行进入请求、路径和其他行不进入请求；原文仅出现在第一次工具续轮，提交后的总结请求不再携带原文。未改动的当前译文不重复附带。选中行被手改后，第二次请求返回的旧提案立即拒绝，全程只发两次请求，不自动重试。

这些是请求结构与文件结果测试，不是新的模型计费样本；输入/输出/思考 Token 仍以实际服务 usage 为准。工作台用法及后续设备测试见[翻译工作台](agent-translation.md)。
