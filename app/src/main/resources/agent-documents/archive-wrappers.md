# Diagnose an unknown wrapper around an archive

1. Record `uu info`, a small header sample from `uu hex`, and the result of `uu l`. Extensions can remain the same after a format or wrapper change. A valid index with incorrect member bytes suggests checking entry decoding before transforming the entire archive.
2. If the signature is missing or displaced, try `uu scan` for embedded data, then `uu guess` for evidence of a short prefix, single-byte adjustment or repeating XOR. These are bounded probes. Treat suggested pipelines as candidates and keep the original file untouched.
3. Test a candidate on a separate copy. If you have a known-good sample, compare headers from the same format and version. For a suspected constant XOR, XOR the corresponding header bytes and check whether the same byte recurs. This only gives a candidate. For a format with automatic magic detection, `uu l "wrapped.dat" --pre "xor 0xAA"` lists a restored view and `uu x "wrapped.dat" -o "staging" --pre "xor 0xAA"` extracts it. For a format selected by extension, use `uu tr` to write a separate decoded file with that extension first. In a quoted pipeline, `skip` runs first and leaves repeating-key offsets relative to the original input.
4. To accept a candidate, require a valid archive structure and usable sample content from more than one entry when available. Prefer a known-good version or a format reader's integrity checks. If only the first bytes match, report the candidate and the missing evidence.
5. A transform applied to the complete archive, a native per-entry filter and protected ZIP/RAR/7z members require different readers. If the available tools cannot describe the observed variant, record the exact failing stage and ask for the expected format, scheme or a known-good sample before changing files.
