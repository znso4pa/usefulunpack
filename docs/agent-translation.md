# Agent 翻译工作台（7.1 开发版）

入口：在共享存储子目录中打开文本预览 → **Agent 翻译工作台**。
先确认处理范围与模型数据说明，再选择输出编码。原文采用预览中选择的读取编码，自动识别结果不符合实际时，应先在预览中切换到正确编码。

## 使用

1. 在模型设置中配置 Base URL、模型名和密钥，沿用现有本地加密配置。发送前可以使用连接测试；连接测试本身会调用模型。
2. 勾选「确认按纯文本逐行处理」。左栏是原始行号与原文，右栏是可编辑草稿；未修改行保持原文。
3. 指定「从行」（从 1 开始）及「行数」（1–8），所选行号用强调色标记。可在底部输入目标语言、术语和语气，再点击「交给 AI」。空输入默认请求翻译成简体中文。
4. AI 先读取本批原文，再提交同样数量、同样顺序的译文。右栏按整批更新，不逐个字符插入；文本不会因模型解释而增加物理行。
5. 点击顶部「对话／译文」切换。模型接口返回的思考、工具活动、解释与错误只放在对话中，不插入译文。两种视图属于同一窗口，不增加 Tab。
6. 「撤销」撤回最近一个 AI 批次或一段连续的手动输入；「还原此行」恢复原文；「还原全部」清空草稿及撤销记录。
7. 「预览」显示按当前草稿重建的文件。最多展示前 65,536 个字符，保存包含整个文件。返回键先退出预览，再回到对话。
8. 「下一批」推进范围，不会自动产生模型请求。取消会停止后续请求，已提交到草稿的译文保留，可用撤销处理。
9. 保存副本需要第三档「文件删改」或第四档权限，并再次确认。输出命名为 `原名.edited.ext`，重名时另取可用名称，原文件保持不变。保存后草稿与撤销仍可继续使用。

## 草稿、权限与隐私

- 工作台会话仅向模型提供 `READ_TRANSLATION_ROWS` / `PROPOSE_TRANSLATION_ROWS` 两个草稿工具，第四档权限也不会给它增加删除、覆盖或运行脚本能力。实际保存由用户按钮和权限确认完成。
- 仅本批选中原文和已有不同译文会发送到用户配置的模型 Base URL。源文件路径、其他行和其他文件不作为工具结果发送。文件内容是待翻译数据，不能替代用户指令。
- 一批原文/已有译文合计最多 12 KiB，每批最多 8 行；大段落需缩小范围，单行仍超限则明确拒绝。输入和生成预算沿用 Agent 设置，不自动重试失败批次。
- 本批原文只读取一次，但保留在本轮工具对话中直到最终反馈完成，供模型核对原文、提案与提交结果。不会中途裁成只有 revision 的回执；模型请求彼此无隐式记忆，过早裁剪会导致总结失去依据。保留范围仍仅为所选 1–8 行、12 KiB，不追加整文件；未修改的「当前译文」不重复附带。
- 草稿随会话保存到应用私有、非备份目录；一个压缩侧车保留一份原始字节与编辑差量。手动输入合并后延迟约 750 ms 保存，AI 批次提交时保存，关闭/切换会话时刷新。保存失败会报告诊断，强制杀进程前尚未完成落盘的输入不能保证恢复。
- 撤销最多保留 32 组、约 256 KiB 文本历史，达到边界会丢弃最旧的撤销组。「还原全部」仍能恢复最初原文。
- 从 Agent 会话列表重新打开可继续草稿；删除会话会删除其草稿和临时文件。延迟保存不会复活被删除的会话。同一草稿会话只允许一个窗口编辑，最终保存完成前保持占用。
- 当前工作台入口要求共享存储中的可读子目录；存储根目录、应用私有目录和符号链接文件被拒绝。归档内容请先解压到共享存储子目录。

## 校验边界

这是按物理行对应的**纯文本**工作台，不是 VN 脚本语法解析器。命令、标签、变量和不确定语法需要人工判断，不能把整个脚本直接视为可翻译正文。
沿用逐行编辑的字面转义/简单命名标记保护，并拒绝 AI 增加物理换行、修改空白行或写入 NUL；编码必须严格可表示。完整 Python 格式字段或 POSIX printf 检查请使用[汉化检查](localization-check.md)，它也不评价翻译质量或保证引擎可运行。

草稿读取时固定原文快照，AI 提交时核对所选行的版本。用户手改、撤销后，迟到结果会以 `STALE_DRAFT` 拒绝，不覆盖手工输入。范围之外的手工修改不会让当前批次失效。
预览同样校验草稿版本；导出前重新读取并核对原文件字节，外部变更会拒绝发布副本。源文件上限 2 MiB、20,000 行、每行 65,536 字符。

## 真机测试建议

在 `Download` 下新建独立测试目录，存一个 UTF-8 文本（第二行包含字面 `\n`，第三行为空）：

```text
Hello {name}
Welcome back.\nNext page.

Keep this line unchanged.
```

- 从预览进入工作台，输出选 UTF-8；从行 1、行数 2，发送翻译指令。确认仅前两行右栏改变，左栏和磁盘原文件不变，对话里的说明不进入文本。
- 点击右栏应能唤出软键盘；同时测试旧「逐行修改」提取行后再点右栏。
- 试一次撤销、手动输入、单行还原和预览；第三档权限确认后保存副本。检查占位符、字面 `\n`、空行及末尾换行。
- AI 等待期间手改选中行，结果回来应报版本冲突并保留手工内容；重新发起批次后才能更新。
- 关闭后从 Agent 会话列表重开，确认草稿和撤销可恢复；删除测试会话，确认列表中消失。
- 横竖屏、输入法打开、切换 Tab、嵌套设置窗口分别测试；只有最上层窗口与独立 Tab 栏应接收输入。

## 开发回归

`TranslationDraftTest` 覆盖字节/编码、版本冲突、撤销、批次原子性、来源变更、保存与会话清理；`AgentClientTest` 使用本地模拟模型检验两工具边界、原文发送次数及失败不重试，不能当作实际模型 Token 计费数据。
离线设备验收沿用[检查命令验收 APK](directory-comparison.md#验证)，另覆盖异步逐行输入框的输入法标记、真实触摸唤出键盘及嵌套窗口输入隔离，不请求模型服务。

底层草稿、快照与结构化批次接口可复用；本版的翻译工具仅挂到已选择文件的应用内会话，尚未向本地 MCP 或 UU/UUT 开放草稿管理接口。

本轮验证：408 项主机单测通过，Lint 0 错误，四语言与共用组件检查通过；单台 Android 真机的 22 项离线检查通过，包含真实触摸弹出软键盘、嵌套输入隔离、CP932 精确输出字节、工作台手改/撤销/自动保存和对话/设置切换。真实模型在独立会话完成小批次翻译及最终反馈复测，用量和修复前失败记录见[公开 Token 矩阵](agent-token-matrix.md#翻译工作台真实模型反馈复查)；这不代表长文件翻译质量验收。横竖屏与多 Tab 的完整交互组合仍需人工测试。
